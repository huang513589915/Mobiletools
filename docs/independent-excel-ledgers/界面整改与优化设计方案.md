## 1. 现状与整改目标

系统面向管理员和客户经理，处理两套彼此独立的 Excel 快照：集团账户欠费明细、专线到期明细。管理员还要管理导入批次、归属匹配异常和账号。界面要服务于实际查数、追溯和维护，不应套用订单系统的业务模块或虚构指标。

本方案参考所提供的 CDK 控制台视觉样例，吸收其清爽的科技蓝、轻量渐变、卡片化信息层次、明确的活动导航、整齐的数据表格和详情抽屉。改造目标如下：

1. 降低目前偏青绿的荧光感，采用清晰、克制的科技蓝作为主色，绿色、琥珀色和红色只用于状态表达。
2. 增强正文、表头、辅助说明和表单标签的可读性，避免小字和低对比度灰字。
3. 统一管理员和客户经理看到的页面框架、导航、标题、按钮、表格、筛选区和详情样式；权限差异仍由现有规则控制。
4. 让管理员能快速区分“当前有效客户经理”和“Excel 原始客户经理”，并清楚查看导入版本和归属异常。
5. 让两个明细页面在大屏、笔记本、平板和窄屏上都能完成主要查询，不因装饰、标签或长文本挤坏布局。

本次只讨论界面呈现与交互整理，不改变 Excel 字段含义、导入校验、快照规则、归属匹配、服务端权限、剩余天数算法和导出内容；不新增风险等级、停机判定、续签状态、任务、消息提醒或其他业务能力。

## 2. 设计语言

### 2.1 色彩与表面

采用偏冷静的科技蓝与中性浅灰作为基础，明亮蓝用于主要操作和当前导航。页面可以使用非常轻的蓝绿径向柔光作背景氛围，但内容区仍以不透明白色卡片为主，保证表格文字和输入控件清楚。

| 用途 | 建议色值 | 使用方式 |
|---|---|---|
| 主操作蓝 | `#2563EB` | 主要按钮、链接、选中图标；避免大面积铺底 |
| 主色浅阶 | `#3B82F6` | 悬停、聚焦、轻量强调 |
| 安全绿 | `#10B981` | 服务正常、匹配成功、成功状态 |
| 警告琥珀 | `#F59E0B` | 待处理、匹配异常、导入警告 |
| 错误红 | `#EF4444` | 阻断错误、失败、明确的负向状态 |
| 页面底色 | `#F4F7FB` | 全局工作区背景 |
| 卡片表面 | `#FFFFFF` | 表格、筛选、摘要等主要内容 |
| 正文 | `#1F2937` | 页面标题、表格内容和关键值 |
| 次级文字 | `#526174` | 字段名、说明和表头 |
| 分隔边框 | `#E2E8F0` | 卡片、表格和控件轮廓 |

状态颜色同时搭配文字标签或图标，不只依赖颜色区分。蓝色强调“可操作/当前选择”，绿色只表示真实成功状态；“当前版本”“历史版本”“待确认”“重复文件”“预检失败”等沿用清晰的文字说明，不用纯色块代替语义。

### 2.2 渐变、玻璃和阴影

- 在登录页背景、应用顶栏或页面背景局部使用低透明度柔光渐变，确保文字下方不出现复杂纹理。
- 毛玻璃仅作为顶栏等少量装饰表面可选效果；主要数据卡片、筛选区、弹窗和抽屉保持实色背景，避免透底降低可读性。
- 边框使用浅灰蓝细线，阴影保持短、淡、低层级。通过留白、对齐和字号建立层次，不依赖重阴影或发光效果。
- 主要按钮可以使用蓝色实底和轻微悬停变化；避免霓虹描边、强荧光色、大面积渐变按钮。

### 2.3 字体和可读性

- 全局采用系统中文无衬线字体栈，例如 Microsoft YaHei、PingFang SC 和系统默认字体；数字字段使用等宽数字或 `font-variant-numeric: tabular-nums`，方便比较金额、日期和数量。
- 辅助说明、状态标签、表格文字建议不低于 12px；表格正文和表单标签建议 13–14px；页面标题 22–28px，卡片标题 16–18px。
- 关键字段（集团名称、金额、日期、剩余天数）用字重和间距强调，避免用更浅的颜色表达重点。
- 次要文案需保持足够对比度。空状态、提示文字和详情字段值也必须清晰可读。
- 长集团名称、文件名、账户 ID 和服务号码在列表中采用合理省略；详情中允许换行或提供复制操作，不能将完整值隐藏掉。

### 2.4 图标

- 统一使用项目现有的 `@ant-design/icons` 图标体系，控制常规尺寸在 16–18px、页面标题图标在 20–22px，并保持线条和语义一致。
- 可将重复使用的菜单、标题和状态图标封装为项目内小组件；只有现有图标无法表达时才补充轻量内联 SVG。
- 不额外引入庞大的图标依赖，也不把图标当作唯一说明；重要操作保留文字按钮和可访问名称。

## 3. 整体框架

### 3.1 登录页

采用深蓝至浅蓝的柔和背景渐变，中央放置白色或半透明浅表面的登录卡片。品牌标记、系统名称和登录表单保持简洁；账号、密码输入框左侧放置语义图标，错误信息靠近表单显示，提交按钮使用主色蓝并显示真实加载状态。

登录页不宣称“实时加密防护”等系统并未实现或无法验证的安全能力。可显示项目真实可获得的服务连接状态，但不能用静态装饰冒充健康检查结果。

### 3.2 登录后工作台框架

- 左侧导航改为参考图中的浅色侧栏风格：白色/半透明浅灰背景、深色文字和蓝色选中条。屏幕空间不足时折叠为抽屉式菜单。
- 菜单按现有模块显示：欠费明细、专线到期明细；管理员额外看到导入批次、归属匹配异常和账号管理。不得显示无对应业务的订单、任务、卡池或系统运行日志菜单。
- 顶部栏左侧显示当前页面名称和简洁的上级路径；右侧显示真实的服务连接状态、当前用户身份和退出入口。当前用户区域按“真实姓名、账号、角色”分层呈现，避免姓名和角色重复，长账号不挤压操作按钮。
- 单层业务页不强行增加多级面包屑。全局刷新应刷新当前页面数据；只有各数据 API 状态明确时才显示对应服务状态。
- 页面主区域采用统一内容最大宽度和一致间距；筛选、列表、详情和弹窗共用相同的圆角、边框、标题和状态标签规范。

### 3.3 信息密度

工作台用于业务查数，优先保证表格行列可读。摘要卡片只在能够直接使用现有查询结果、且确实帮助管理员判断当前快照情况时采用，例如当前筛选记录数或批次校验行数。不得增加模拟数量、虚构风险数据或不必要的大型 KPI 仪表盘。

## 4. 页面整改方案

### 4.1 欠费明细

**页面头部**：显示“欠费明细”标题、月度快照说明和当前统计日期。管理员可见刷新和导出筛选结果操作；客户经理仍只看到授权范围内的记录。

**筛选区**：将统计月份、集团、账户 ID、承载产品名称、管理员的客户经理筛选组合在一块浅底卡片中。重置与导出放在筛选组末尾；窄屏时按多行自然排列。保留目前确认的筛选含义和默认最新快照交互。

**列表**：固定展示日期、集团编码、集团名称、Excel 原始客户经理、当前有效客户经理、账户 ID、承载产品名称、期末欠费金额、账龄和详情入口。金额右对齐并用等宽数字；“是否达到停机标准”仅在详情查看，不以颜色或标签在列表暗示风险。

**详情抽屉**：顶部展示集团、账户和归属状态；接着展示重要规范化字段、Excel 原始归属和系统当前有效归属；底部按原 Excel 列顺序展示所有非空表头原始字段。空值用“—”，有效数值 0 显示为 `0`。保留来源批次、工作表和原始行号等追溯信息。

### 4.2 专线到期明细

沿用欠费页的页面头部、筛选卡片、表格和详情抽屉样式，保证两张账本切换时不用重新学习交互。

**筛选区**：统计日期、集团、产品编码/名称、管理员的当前有效客户经理，以及剩余天数最小值和最大值。显示“剩余天数按系统当前日期计算”的简短说明；导出仍按既定规则不包含派生剩余天数。

**列表**：显示统计日期、集团编码、集团名称、产品编码、产品名称、成员服务号码、Excel 原始客户经理、当前有效客户经理、计费截止日期、剩余天数和详情入口。成员状态只在详情出现。剩余天数要便于扫描，负数可用低饱和红色并明确标成“逾期 N 天”，非负值保持中性蓝灰，不额外设置未确认的风险阈值。

**详情抽屉**：按前述结构显示集团、产品和服务号码概要、剩余天数、两种客户经理归属、来源批次位置，以及所有非空表头的 Excel 字段。计费截止日期用于剩余天数展示；合同到期日不参与计算，仍按业务约定作为原始详情字段查看。

### 4.3 导入批次与上传预览

- 上传操作以清晰的三步状态呈现：选择数据类型和工作簿、检查预览和差异、确认或取消本次预检。步骤展示当前进度，不改变既有导入状态机。
- 预览顶部用摘要卡片展示数据来源、统计日期、文件名、总行数、有效/警告/错误数量和修正版差异。阻断错误使用红色说明并标出工作表和原始行；非阻断归属异常使用琥珀色提示。
- 预览表格保留工作表、原始行号、业务键、Excel 客户经理及问题摘要；展开行查看原始字段。
- 确认成为当前版本与取消本次上传使用不同按钮层级；取消需二次确认并说明不会写入正式快照。重复文件不提供确认入口。
- 批次表格让来源、日期、文件名、状态、版本标记和校验数量易于扫描；原始工作簿下载和批次追溯信息保持可见。

### 4.4 归属匹配异常

- 页面上方放置来源、统计日期、集团、Excel 姓名、批次和处理状态筛选。批量操作区在有选择记录时突出显示，并明确本次选中数量和数据来源。
- 表格强调 Excel 原始客户经理、匹配失败原因、当前有效客户经理和批次位置；失败原因较长时列表省略，详情完整显示。
- 选择单行、当前页或当前筛选结果的交互要有一致的选择状态；目标客户经理、可选处理说明和确认按钮放在同一区域。跨欠费/专线来源混选继续受现有业务限制。
- 详情抽屉分区展示匹配信息、Excel 原始字段和归属变更历史，避免把大量原始数据挤进列表。
- 未分配记录仍显示“未分配（归属匹配异常）”；人工分配后显示当前有效客户经理，原始 Excel 姓名保留。

### 4.5 账号管理

- 账号列表使用清晰的状态 Tag 区分管理员/客户经理和启用/停用；显示登录账号、真实姓名、角色和更新时间等现有字段。
- 新建账号表单分为真实姓名、登录账号、角色、密码等逻辑区块；拼音建议与账号冲突提示紧邻登录名。表单校验错误放在字段旁。
- 停用操作仍使用确认提示；创建、启停和真实姓名精确匹配等业务逻辑不随视觉升级改变。

## 5. 组件和交互规范

- **按钮层级**：每个区域仅保留一个主操作，刷新、重置等用次级按钮，删除/取消或不可逆语义用危险色和确认提示。
- **筛选交互**：标签和占位文案明确字段含义；清除单项使用控件自身清除能力；重置恢复页面默认条件，不清除用户身份或授权限制。
- **表格**：统一表头背景、行高、对齐、悬停色、空状态、加载状态和分页；长表格允许横向滚动，固定操作列不得遮挡重要数据。
- **详情**：使用右侧抽屉承载记录上下文、规范化字段和原始字段；抽屉宽度随桌面和窄屏调整，窄屏改为近全屏宽度。
- **状态反馈**：加载、无数据、无匹配结果、请求失败、导入警告和阻断错误分别设计，避免只显示“接口请求失败”等缺少操作指引的信息。失败时保留筛选条件并提供重试。
- **动效**：只用于菜单切换、按钮反馈、抽屉和弹窗进入等短交互；尊重减少动态效果偏好，不加入持续闪烁或装饰性大幅动画。
- **可访问性**：交互控件保留文字或 `aria-label`；键盘焦点清楚可见；状态除颜色外同时有文本，文字和背景有足够对比度。

## 6. 响应式方案

| 屏幕宽度 | 布局策略 |
|---|---|
| ≥ 1440px | 固定侧栏、完整顶栏、筛选控件尽量单行、表格充分利用宽度 |
| 1024–1439px | 保留侧栏，筛选控件允许换行，压缩卡片间距但不缩小字号 |
| 768–1023px | 导航可折叠，筛选按两列或多行布局，表格保留横向滚动 |
| < 768px | 导航改为抽屉菜单；筛选纵向排列；服务状态和用户身份适度收纳；详情抽屉近全屏；主要按钮保证触控尺寸 |

窄屏下不通过隐藏关键字段来伪装完整表格。可以允许水平滚动、调整非关键列宽或把次级信息放进详情；身份、集团、账户/服务号码、关键金额/日期和操作入口需保持可找到。

## 7. 分阶段实施建议

本章节是后续实施建议，不是当前授权执行的代码修改。

| 阶段 | 范围 | 交付与检查 |
|---|---|---|
| 阶段 1：设计令牌与全局框架 | 色板、字体、间距、边框、按钮、侧栏、顶栏、登录页、用户身份区 | 管理员与客户经理登录后框架一致；无姓名/角色重复，导航权限保持原样 |
| 阶段 2：两张明细账本 | 欠费、专线筛选区、列表、状态显示、详情抽屉、加载/空/错误状态 | 字段和筛选逻辑不变；原始/有效归属清楚；原始详情完整可读 |
| 阶段 3：管理员页面 | 导入批次、上传预览/取消确认、归属异常批量处理、账号管理 | 导入、取消、分配和账号行为与现有规则一致；校验信息容易定位 |
| 阶段 4：响应式与视觉验收 | 桌面、笔记本、平板、手机宽度；键盘与对比度检查 | 浏览器实测并留存各关键页面截图，修复溢出、遮挡和小字问题 |

建议每个阶段先在当前真实数据结构和角色权限下完成 UI 评审，再逐页实施。只要现有接口已能提供数据，视觉实现不需要改业务规则；如果组件需要接口未提供的指标，应先标明数据缺口，避免填入静态假值。

## 8. 验收标准

1. 主色为低荧光感科技蓝，绿色、琥珀色和红色仅在真实状态语义下出现，整体与参考图的清爽浅色工作台风格一致。
2. 页面辅助文字和状态文字至少 12px；表格正文清晰，表头、正文和辅助说明有明显层次。
3. 管理员/客户经理身份显示姓名、账号和角色，含义清楚且不会因为重复文案、过长账号导致顶栏错位。
4. 管理员菜单仍只包含现有管理页面；客户经理不能通过页面入口看到管理员功能，服务端权限保持不变。
5. 欠费和专线列表字段、筛选项、排序和导出语义不变；页面视觉规范一致。
6. 专线剩余天数仍按既定系统当前日期计算；没有新增未确认的风险区间、风险等级或续签状态。
7. 详情可查看所有 Excel 非空表头原始字段、原始客户经理和当前有效客户经理；空值与数值 0 区分显示。
8. 上传预览、确认、取消、重复提示、修正版差异、异常批量分配和账号维护都保留原有功能及确认步骤。
9. 页面在 1440px、1280px、768px 和 390px 视口下检查；无横向页面溢出、文字被裁切、固定操作遮挡和不可点击控件。大型表格可在容器内部横向滚动。
10. 浏览器实测管理员和客户经理各一组关键流程，截图覆盖两个明细页、上传预览、归属异常、账号管理和窄屏导航。

## 9. 明确不纳入本次视觉整改的内容

- 新增订单、任务、日志终端、卡池、套餐、通知、系统策略等其他产品模块。
- 新增风险阈值、风险评分、停机标准判定流程、续签处理状态、自动督办和消息通知。
- 重新设计数据库、导入规则、Excel 字段、客户归属算法、账号认证和数据权限。
- 另建前端客户端/管理端两个应用；当前是按角色显示菜单和数据范围的单一应用。
- 引入未经验证的统计指标、实时加密宣传、模拟服务状态或假数据仪表盘。

## 10. 评审结论建议

建议采纳科技蓝与浅色工作台方向，优先完成全局框架和用户身份区，然后统一改造欠费、专线两个高频查询页面，再整理管理员导入、异常和账号页面。参考图中的柔光背景、轻玻璃和卡片层次可作为视觉灵感，但数据表格与详情仍应以清晰、稳定和真实业务信息优先。
