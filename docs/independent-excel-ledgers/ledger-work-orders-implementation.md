# 工单与跟进说明实施记录

本次变更在独立的欠费和专线数据域中增加可追溯处理记录，不建立两张 Excel 表之间的业务关联。

## 数据库迁移

在隔离测试库（建议数据库名 `arrears_management_test`）确认已经执行 V1、V2、V4 后执行：

```powershell
Set-Location D:\code\Mobiletools
mysql --default-character-set=utf8mb4 -u YOUR_MYSQL_USER -p arrears_management_test --execute="SOURCE db/migrations/V5__ledger_work_orders_and_follow_ups.sql"
mysql --default-character-set=utf8mb4 -u YOUR_MYSQL_USER -p arrears_management_test --execute="SOURCE db/tests/V5_ledger_work_orders_constraints.sql"
```

在已安装 MySQL 8.4 的开发机上，可直接运行 `./db/tests/run-v5-isolated.ps1`。该脚本启动临时本地 MySQL 实例，自动准备隔离表结构、运行迁移和约束验证，然后关闭并清理该临时实例。

V5 只新增欠费工单、两类欠费记录、两类专线记录及索引，并为当前有效欠费快照幂等补建“待处理”工单；不会删除快照、专线状态或导入批次。重复执行回填不会增加工单行。生产库执行前必须先备份，回滚应用时停止工单写入后再回退应用版本；不通过破坏性逆向 SQL 自动删除这些历史表。

## 工单行为

- 欠费自然键为 `统计月份 + 账户 ID`，状态为“待处理、跟进中、已结清”。
- 专线自然键仍为 `统计日期 + 成员服务号码`，状态为“待处理、跟进中、已续签、不续签”。
- 状态可以任意切换；实际变化写状态历史。
- 目标状态为“跟进中”时可选填说明。说明首尾空白会被去除，空白说明不写入；说明追加保存，保留填写人和时间。
- 当前已是“跟进中”时，可以只追加说明。状态不变且无说明时视为无操作，不更新时间。
- 同月/同日修正版只切换快照引用，复用自然键工单；新增行建立待处理工单，移除行只从当前版本隐藏，历史不会删除。
- 详情时间线合并状态变化和说明，按发生时间及稳定来源编号排序。

## 权限和导出

管理员可查看和处理全部工单；客户经理按当前快照的有效归属查看和处理，未分配记录仅管理员可见。历史月份仍可编辑。

管理员可从欠费页面导出固定 12 列的欠费工单报表；其中不包含跟进说明或状态历史。原始欠费导出保持原字段边界，同时应用页面当前筛选（包括工单状态），但不新增工单列。两种导出互不替代。专线原始导出和续签工单报表也不包含跟进说明。
