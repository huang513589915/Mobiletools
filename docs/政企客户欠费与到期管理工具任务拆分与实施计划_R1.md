# 政企客户欠费与到期管理工具任务拆分与实施计划

版本：1.0（R1）  
日期：2026-10-09  
依据文档：政企客户欠费与到期管理工具需求规格说明书_R1  
文档用途：将客户需求拆分为可执行、可交付、可验证的实施任务

## 1. 拆分原则和范围

本任务拆分围绕“统一数据、风险预警、任务督办、处理闭环、安全部署、试点验收”展开。每项任务均明确目标、工作范围、交付成果、建议负责人、优先级、建议时间节点、验收标准和依赖关系。

建议以“欠费及专线到期管理”作为第一阶段最小可用范围。复杂预测模型、自动外呼、自动停复机、外部客户门户和未经确认的跨系统深度改造不列入第一阶段。

负责人使用角色名称表示，正式人员需在项目启动后确认：

- 业务负责人：代表政企客户经理和后台人员确认业务规则、流程和验收结果。
- 需求分析/项目经理：负责需求整理、计划、协调和交付管理。
- 数据负责人：负责数据源、字段口径、数据质量和数据接入。
- 平台/架构负责人：负责公司内部平台、账号、接口和部署方案。
- 前端负责人：负责页面、交互和用户操作体验。
- 后端负责人：负责业务服务、任务流程、规则和接口。
- 安全/运维负责人：负责安全审查、环境、日志、监控和上线。
- 测试/试点负责人：负责测试、用户试用、问题闭环和验收材料。

## 3. 子任务详细说明

### T01 项目启动与需求确认

**目标和范围**

确认项目目标、第一阶段范围、参与人员、决策机制、沟通机制和最终验收人。对原始需求中的事实、建议和待确认问题进行分类，形成项目基线。

**具体工作**

- 确认欠费、余额、专线到期和续签管理的第一阶段目标。
- 确认试点部门、试点客户经理和业务范围。
- 确认业务负责人、数据负责人、平台负责人和验收负责人。
- 建立需求问题清单、风险清单和决策记录。

**交付成果**

- 项目启动纪要。
- 项目角色和职责清单。
- 第一阶段范围确认单。
- 需求问题和决策跟踪表。

**建议负责人和节点**

- 负责人：业务负责人、需求分析/项目经理。
- 时间：第1周。

**验收标准**

- 业务负责人确认范围、人员和验收方式。
- 所有未决问题均有责任人和计划确认时间。

**依赖关系**

- 前置：无。
- 后续：T02、T03、T04、T06。

### T02 现状流程与目标流程梳理

**目标和范围**

把目前依靠短信、线下表格、台席明细和人工台账的管理方式，转化为可执行的现状流程和目标流程。

**具体工作**

- 梳理专线到期、欠费明细、余额预警、客户跟进、逾期督办和异常核查流程。
- 标识每个环节的输入、处理人、输出、时限和风险点。
- 设计目标流程：数据进入、规则判断、任务生成、客户经理处理、后台复核、关闭和归档。
- 明确哪些环节自动化，哪些环节必须人工确认。

**交付成果**

- 现状业务流程图。
- 目标业务流程图。
- 角色职责和流程节点清单。
- 任务状态流转说明。

**建议负责人和节点**

- 负责人：需求分析/项目经理、业务负责人。
- 时间：第1周。

**验收标准**

- 客户经理和后台人员能够通过流程图确认实际工作方式。
- 每个任务状态都有进入条件、处理动作和退出条件。

**依赖关系**

- 前置：T01。
- 后续：T05、T09、T10、T16。

### T03 数据源与字段口径梳理

**目标和范围**

确定欠费、余额、停机状态、专线到期、客户归属和客户经理信息的来源、字段、更新频率和权威口径。

**具体工作**

- 盘点现有系统、线下表格和台席明细。
- 建立数据源清单、字段映射表和数据责任人清单。
- 确定客户唯一标识、业务唯一标识和客户经理匹配规则。
- 评估接口接入、文件导入或人工上传方式。
- 定义数据冲突、缺失、重复和过期的处理规则。

**交付成果**

- 数据源清单。
- 数据字典和字段映射表。
- 数据质量问题清单。
- 数据接入方式评估结论。

**建议负责人和节点**

- 负责人：数据负责人、业务负责人。
- 时间：第1-2周。

**验收标准**

- 每类核心数据都有明确来源、更新时间、责任人和使用口径。
- 能够使用样例数据完成客户和业务的关联匹配。

**依赖关系**

- 前置：T01。
- 后续：T05、T07、T08、T09、T13。

### T04 平台能力与部署可行性评估

**目标和范围**

确定公司内部可用的AI工具、业务平台、消息平台、身份认证、文件存储、日志和部署环境。

**具体工作**

- 与平台资源负责人确认现有可复用能力。
- 评估内部平台是否支持数据导入、任务流转、定时任务、消息提醒和权限控制。
- 确定开发、测试和生产环境。
- 评估是否允许使用数据库、低代码平台、工作流平台或智能表格。
- 输出初步部署架构和技术边界。

**交付成果**

- 平台能力清单。
- 部署可行性评估报告。
- 初步技术架构和环境方案。
- 外部依赖和限制清单。

**建议负责人和节点**

- 负责人：平台/架构负责人、安全/运维负责人。
- 时间：第1-2周。

**验收标准**

- 明确第一阶段采用的平台、账号体系、数据存储和消息渠道。
- 明确不可用能力及替代方案。

**依赖关系**

- 前置：T01。
- 后续：T07、T11、T14、T15、T17。

### T05 预警规则和任务规则确认

**目标和范围**

将业务人员的经验判断转化为可配置、可解释、可验证的预警和任务规则。

**具体工作**

- 确认余额不足、欠费金额、欠费天数、停机风险和专线到期提前天数。
- 确认一般、重要、紧急等风险等级及其处理时限。
- 确认预警是否需要人工确认。
- 确认重复预警、预警解除、误报、暂缓、关闭和重新触发规则。
- 确认任务自动分派、转派、逾期、升级和复核规则。

**交付成果**

- 预警规则清单。
- 任务规则清单。
- 风险等级和处理时限配置表。
- 规则样例和计算示例。

**建议负责人和节点**

- 负责人：业务负责人、需求分析/项目经理。
- 时间：第2周。

**验收标准**

- 使用样例数据能够计算出预期预警等级和任务结果。
- 每条规则都有触发条件、处理动作和关闭条件。

**依赖关系**

- 前置：T02、T03。
- 后续：T09、T10、T11、T14、T16。

### T06 用户角色与权限模型设计

**目标和范围**

将客户经理、后台人员、数据提供人员、督办人员和系统管理员的职责转化为菜单、数据和操作权限。

**具体工作**

- 确认正式角色名称和账号来源。
- 确认按客户经理、部门、区域、产品或其他维度划分数据权限。
- 设计查看、导入、修改、分派、催办、关闭、导出、规则配置和日志查看权限。
- 明确敏感字段脱敏规则和跨团队查询限制。

**交付成果**

- 角色权限矩阵。
- 数据权限规则。
- 菜单和按钮权限清单。
- 敏感字段和脱敏规则清单。

**建议负责人和节点**

- 负责人：需求分析/项目经理、平台/架构负责人。
- 时间：第2周。

**验收标准**

- 使用测试账号能够验证不同角色的可见范围和可操作范围。
- 权限矩阵覆盖所有核心页面和关键操作。

**依赖关系**

- 前置：T01、T03。
- 后续：T07、T08、T10、T14、T15、T16。

### T07 数据导入与数据接入模块

**目标和范围**

实现欠费、余额、专线到期和客户归属数据的导入或系统接入，并保留来源和批次信息。

**具体工作**

- 提供标准导入模板和字段说明。
- 支持数据格式、必填项、重复数据、关联数据和日期金额校验。
- 支持预检、错误明细、批次记录和结果统计。
- 如具备接口条件，建立定时或手动同步机制。
- 处理数据导入失败、重复导入和部分成功场景。

**交付成果**

- 数据导入页面或接口。
- 导入模板。
- 字段校验和错误码说明。
- 数据批次和导入日志。
- 接口接入说明或文件导入说明。

**建议负责人和节点**

- 负责人：后端负责人、数据负责人。
- 时间：第3-4周。

**验收标准**

- 正确数据可成功导入，错误数据可定位到行和字段。
- 导入批次可查询，来源、导入人、时间和结果可追溯。
- 重复导入不会产生不可控重复数据。

**依赖关系**

- 前置：T03、T04。
- 后续：T08、T09、T13、T15。

### T08 客户及业务统一台账

**目标和范围**

形成客户、业务、欠费、余额、到期、续签和归属信息的统一展示和查询基础。

**具体工作**

- 设计客户主数据、业务数据、欠费记录、到期记录和处理状态的关联关系。
- 支持按客户、客户经理、业务类型、区域、风险等级和时间范围查询。
- 展示数据来源、更新时间、批次、当前状态和异常标识。
- 提供客户详情和历史处理记录。

**交付成果**

- 客户及业务台账页面。
- 数据模型或数据映射说明。
- 查询条件和列表字段清单。
- 客户详情和历史记录展示。

**建议负责人和节点**

- 负责人：后端负责人、前端负责人。
- 时间：第3-4周。

**验收标准**

- 能够通过客户或业务标识查到关联的余额、欠费、到期和处理记录。
- 列表和详情中的数据来源、更新时间和状态含义清晰。

**依赖关系**

- 前置：T03、T06、T07。
- 后续：T09、T10、T12、T13、T14。

### T09 风险预警引擎

**目标和范围**

根据已确认规则计算客户风险，生成可解释的预警记录，支持预警确认和解除。

**具体工作**

- 实现余额、欠费、停机风险和到期提醒规则。
- 支持定时计算和人工重新计算。
- 记录触发规则、触发字段、触发时间、风险等级和责任人。
- 支持预警确认、误报、暂缓、解除和重新触发。
- 防止同一客户同一事项在短时间内重复生成无效预警。

**交付成果**

- 预警计算服务。
- 预警列表和详情页面。
- 规则触发明细。
- 预警状态流转和操作日志。

**建议负责人和节点**

- 负责人：后端负责人、业务负责人。
- 时间：第4-5周。

**验收标准**

- 使用已确认样例数据，预警结果与规则计算示例一致。
- 每条预警可解释、可追溯、可人工处理。

**依赖关系**

- 前置：T05、T07、T08。
- 后续：T10、T11、T12、T14、T16。

### T10 任务生成、分派和处理闭环

**目标和范围**

将预警和到期事项转化为客户经理可执行的任务，并形成从接收、跟进到关闭的闭环。

**具体工作**

- 设计任务来源、任务类型、责任人、处理时限和完成条件。
- 支持自动分派、后台分派、转派和重新指派。
- 支持待处理、处理中、待核实、已完成、已关闭、逾期等状态。
- 支持跟进记录、缴费结果、续签结果、备注和附件。
- 支持需要后台复核的任务关闭流程。

**交付成果**

- 任务中心页面。
- 任务状态流转和操作接口。
- 任务分派和转派功能。
- 跟进记录和处理结果表单。
- 任务历史和关闭记录。

**建议负责人和节点**

- 负责人：后端负责人、前端负责人。
- 时间：第4-6周。

**验收标准**

- 客户经理能够完成查看、跟进、提交结果和关闭任务。
- 后台能够查询任务全过程并复核必要任务。
- 任务责任人、处理时限和结果记录完整。

**依赖关系**

- 前置：T05、T06、T08、T09。
- 后续：T11、T12、T16。

### T11 提醒、催办和逾期督办

**目标和范围**

建立任务提醒、逾期识别、催办和升级机制，减少任务遗漏。

**具体工作**

- 确认内部提醒渠道和消息模板。
- 支持任务创建提醒、临近到期提醒和逾期提醒。
- 支持客户经理自查待办和直属负责人查看团队逾期任务。
- 支持催办、升级、暂缓和提醒记录。
- 处理消息发送失败和重复发送问题。

**交付成果**

- 提醒和催办服务。
- 消息模板。
- 逾期任务列表。
- 催办和升级记录。
- 发送失败日志和补发机制说明。

**建议负责人和节点**

- 负责人：后端负责人、平台/架构负责人。
- 时间：第6周。

**验收标准**

- 任务达到配置条件后能够生成对应提醒。
- 逾期任务能够被识别并按权限展示。
- 消息发送、失败和补处理过程可追溯。

**依赖关系**

- 前置：T04、T10。
- 后续：T16、T17。

### T12 后台监控、查询和统计导出

**目标和范围**

为后台人员和督办人员提供整体风险、任务处理和欠费回收情况的查询、统计和导出能力。

**具体工作**

- 设计风险客户、欠费金额、待办、逾期、已处理和数据异常指标。
- 支持按区域、客户经理、业务类型、风险等级、状态和时间筛选。
- 支持明细查询、统计汇总和导出。
- 根据权限限制统计范围和导出范围。
- 明确指标口径，避免不同页面统计结果不一致。

**交付成果**

- 后台监控首页或工作台。
- 查询列表和筛选条件。
- 统计指标说明。
- 导出功能和导出权限控制。

**建议负责人和节点**

- 负责人：前端负责人、后端负责人。
- 时间：第5-6周。

**验收标准**

- 统计结果与明细数据可核对。
- 不同角色看到的数据范围符合权限要求。
- 导出内容与筛选条件一致并记录日志。

**依赖关系**

- 前置：T08、T09、T10。
- 后续：T16、T17。

### T13 数据异常核查和来源追溯

**目标和范围**

处理短信、线下明细和系统数据不一致的问题，建立异常标记、核查和反馈记录。

**具体工作**

- 识别缺失、重复、冲突、过期、无法匹配和状态异常数据。
- 展示同一客户或业务的多来源数据差异。
- 支持后台人员标记异常原因、核查结论和后续处理人。
- 保留原始数据、修正记录和处理历史。

**交付成果**

- 数据异常列表。
- 来源对比和核查页面。
- 异常处理状态和原因字典。
- 数据修正和反馈记录。

**建议负责人和节点**

- 负责人：数据负责人、后端负责人。
- 时间：第5-6周。

**验收标准**

- 能够定位异常数据的来源、批次和更新时间。
- 异常记录有处理状态、责任人和核查结论。
- 系统不会静默覆盖存在差异的数据。

**依赖关系**

- 前置：T07、T08。
- 后续：T14、T16。

### T14 AI查询和辅助回答能力

**目标和范围**

在内部批准的平台内，为授权用户提供基于台账、预警和任务数据的查询摘要和辅助回答。

**具体工作**

- 设计客户风险、任务、到期和数据来源查询场景。
- 控制AI可访问的数据范围和字段范围。
- 回答中展示数据更新时间、来源和风险依据。
- 对数据冲突、缺失和无法确认情况给出明确提示。
- 禁止AI直接替代停机、扣款、账务修改等业务决策。

**交付成果**

- AI查询场景清单。
- 提示词或问答配置说明。
- 权限过滤和数据引用方案。
- 典型问题测试集。
- AI回答质量和安全评估记录。

**建议负责人和节点**

- 负责人：AI/平台负责人、业务负责人。
- 时间：第6-7周，可晚于核心业务功能。

**验收标准**

- 典型问题回答能够引用正确数据，并标识更新时间和来源。
- 越权用户无法通过问答获取无权限数据。
- 数据不确定时能够明确说明，不编造结论。

**依赖关系**

- 前置：T06、T08、T09、T13、T04。
- 后续：T16、T17。

### T15 安全、日志和运行监控

**目标和范围**

确保系统在内部环境中具备身份认证、权限控制、敏感数据保护、操作审计和基础运行监控能力。

**具体工作**

- 接入公司统一认证或确定登录方式。
- 实施角色权限、数据权限和字段脱敏。
- 记录登录、查询、导入、导出、规则修改、任务分派和权限变更等关键操作。
- 建立接口异常、导入失败、任务生成失败和消息发送失败日志。
- 完成开发、测试和生产环境隔离及安全检查。

**交付成果**

- 安全设计说明。
- 权限和脱敏配置。
- 操作日志和审计报表。
- 运行监控和异常处理说明。
- 安全评审问题清单及整改记录。

**建议负责人和节点**

- 负责人：安全/运维负责人、平台/架构负责人。
- 时间：第3-7周，贯穿开发。

**验收标准**

- 未授权用户无法访问受限页面、接口和数据。
- 关键操作能够追溯到用户、时间、对象和结果。
- 测试和生产环境边界、敏感数据处理和日志要求通过审核。

**依赖关系**

- 前置：T04、T06、T07。
- 后续：T16、T17。

### T16 测试、试点、培训和验收

**目标和范围**

验证系统核心功能、数据准确性、权限安全和业务可用性，组织试点用户完成真实业务流程。

**具体工作**

- 编写功能、接口、权限、数据质量、异常和安全测试用例。
- 使用样例数据验证导入、预警、任务、督办和统计。
- 组织客户经理和后台人员试用。
- 收集问题，分级处理并形成闭环。
- 编制培训材料、用户操作手册和验收记录。

**交付成果**

- 测试计划和测试用例。
- 测试执行记录和缺陷清单。
- 试点用户反馈和问题闭环表。
- 培训材料和操作手册。
- 试点验收报告。

**建议负责人和节点**

- 负责人：测试/试点负责人、业务负责人。
- 时间：第7-9周。

**验收标准**

- 核心流程通过测试，重大缺陷关闭。
- 试点用户能够独立完成核心业务处理。
- 业务负责人确认交付范围、遗留问题和上线条件。

**依赖关系**

- 前置：T10、T11、T12、T13、T15。
- 后续：T17、T18。

### T17 上线部署和运维移交

**目标和范围**

将通过试点验收的版本部署到生产环境，并完成运行维护交接。

**具体工作**

- 完成生产环境部署、配置和数据初始化。
- 配置用户、角色、数据权限、规则、提醒和日志。
- 执行上线前备份、回滚和应急方案检查。
- 完成上线验证和首期运行观察。
- 向运维和业务管理员移交系统文档。

**交付成果**

- 生产部署记录。
- 上线检查清单。
- 回滚和应急处理方案。
- 运维手册和管理员手册。
- 上线后问题跟踪表。

**建议负责人和节点**

- 负责人：安全/运维负责人、平台/架构负责人。
- 时间：第9-10周。

**验收标准**

- 生产环境核心流程可用。
- 用户和权限配置正确。
- 监控、日志、备份和应急联系人已生效。
- 业务和运维负责人完成移交确认。

**依赖关系**

- 前置：T16。
- 后续：T18。

### T18 后续扩展评估

**目标和范围**

根据试点效果评估是否扩展到专线续签、合同到期、客户服务事项和其他台账管理场景。

**具体工作**

- 对比试点前后的人工工作量、漏提醒数量和任务及时率。
- 收集客户经理、后台人员和管理人员的改进建议。
- 评估数据接入、规则复用和平台扩展成本。
- 形成第二阶段候选范围和优先级。

**交付成果**

- 试点效果评估报告。
- 用户反馈汇总。
- 第二阶段需求清单。
- 后续迭代计划和资源估算。

**建议负责人和节点**

- 负责人：业务负责人、需求分析/项目经理。
- 时间：试点上线后2-4周。

**验收标准**

- 明确是否扩展、扩展哪些场景以及扩展依据。
- 后续需求形成独立版本，不直接混入第一阶段范围。

**依赖关系**

- 前置：T16、T17。
- 后续：第二阶段项目。

## 4. 建议实施节奏

### 阶段一：需求和可行性确认（第1-2周）

完成 T01-T06。输出需求基线、流程、数据口径、平台评估、规则和权限设计。

### 阶段二：核心数据和业务闭环开发（第3-6周）

完成 T07-T13、T15 的核心部分。优先实现导入、统一台账、预警、任务闭环、后台查询和安全审计。

### 阶段三：智能辅助和质量验证（第6-9周）

完成 T11-T16。AI能力建议在核心数据和权限稳定后接入，避免在数据口径未定时建设问答能力。

### 阶段四：上线和迭代评估（第9-10周及以后）

完成 T17，上线后根据 T18 评估第二阶段。

→ `T16 测试试点验收`  
→ `T17 上线部署`  
→ `T18 后续扩展评估`

### 5.2 可并行任务

- T03 数据梳理、T04 平台评估可并行。
- T05 规则确认和 T06 权限设计可并行。
- T07 数据接入和 T15 安全基础设计可并行。
- T11 提醒督办、T12 查询统计、T13 异常核查可在 T08/T09/T10 基础上并行开发。

### 5.3 不能提前的任务

- 在T03完成前，不宜锁定数据库字段和接口字段。
- 在T05完成前，不宜开发正式预警计算逻辑。
- 在T06完成前，不宜开放生产数据查询和导出。
- 在T10完成前，不宜进行完整的督办和逾期验收。
- 在T15完成安全检查前，不宜使用真实客户敏感数据开展试点。

## 6. 第一阶段建议验收清单

- 数据能够按确定方式进入系统，并保留来源、批次和更新时间。
- 客户经理能够看到本人客户的欠费、余额、专线到期和风险信息。
- 系统能够按确认规则生成预警，并展示触发依据。
- 系统能够生成、分派、提醒、催办和关闭任务。
- 客户经理能够登记缴费、续签、联系和其他处理结果。
- 后台能够查看整体风险、待办、逾期和数据异常。
- 不同角色只能访问授权范围内的数据。
- 导入、修改、导出、分派、催办和关闭操作可追溯。
- 试点用户能够完成至少一轮真实业务处理。
- 上线所需的部署、操作、运维、安全和验收文档齐全。

## 7. 需要在项目启动会上确认的事项

1. 第一阶段试点的客户经理、区域、业务类型和数据范围。
2. 欠费、余额、停机状态、到期和客户归属的正式数据源。
3. 余额、欠费和到期的具体预警阈值及任务处理时限。
4. 任务分派、逾期升级和后台复核的责任关系。
5. 公司内部可用平台、账号体系、提醒渠道和部署环境。
6. 生产数据是否允许进入AI上下文、是否留存以及留存周期。
7. 最终需求确认人、技术评审人、安全审核人和验收人。
8. 计划上线时间、试点周期和后续推广方式。
