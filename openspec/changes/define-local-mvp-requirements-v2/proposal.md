# Proposal

## Why

当前项目已有登录、客户查询、任务查询和演示页面，但真实的五类 Excel 数据、客户关联、重复导入、风险计算和督办闭环尚未形成统一的可验证契约。需要在不扩大为微服务或外部通知平台的前提下，将本地 MVP 的页面、业务规则、数据库模型和实施顺序明确下来。

## What Changes

- 以五工作表导入契约和五个独立业务 Excel 作为 V1 数据接入范围。
- 建立客户、业务、欠费、到期、风险、任务、跟进和导入批次之间的可追溯关联。
- 增加登录、用户账号、管理员与客户经理权限及客户范围控制的正式规格。
- 规划风险工作台、客户风险台账、任务中心、数据接入、规则与审计页面的正式行为。
- 明确重复导入、空值不覆盖、孤立记录剔除、批量事务和风险重算规则。
- 保持 Spring Boot 模块化单体、Spring JDBC、MySQL 和本地浏览器访问方式；本轮只更新规划工件，不执行建表或迁移。

## Capabilities

### New Capabilities

- `user-auth-permission`: 登录、退出、会话保护、用户账号管理、管理员与客户经理权限。
- `risk-workbench`: 风险工作台的概览、筛选、跳转和数据状态展示。
- `risk-rule-and-audit`: 四条 V1 风险规则、风险计算/重算、异常记录和操作审计。
- `data-ingestion-traceability`: 补充五工作表/独立文件契约、业务唯一性、幂等、空值和批次追溯。
- `customer-risk-ledger`: 补充客户、业务、账单、到期与风险结果的正式台账行为及权限范围。
- `follow-up-task-management`: 补充任务幂等、来源关联、风险与人工处理分离及客户经理范围。

### Modified Capabilities

- 无。当前项目尚无已归档的 `openspec/specs/` capability；本变更首次建立以上六项长期能力规格。

## Impact

- 页面：登录、风险工作台、客户台账及详情、任务中心、数据接入、规则与权限、异常和审计查询。
- 后端：认证授权、导入预检/确认、台账查询、任务生命周期、风险计算和审计接口。
- 数据库：保留并扩展 `app_user`、`customer`、`task`、`import_batch`、`import_row`、`follow_up`；规划业务、风险、范围和审计表。
- 依赖：继续评估 Apache POI；不默认新增 Redis、消息队列、Quartz、微服务或第二套数据访问框架。
- 现有演示页面仅作为交互参考，不能视为正式业务能力已完成。
