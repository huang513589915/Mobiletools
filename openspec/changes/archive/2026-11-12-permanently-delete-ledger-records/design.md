# Design

## Context

当前台账由批次行、快照、有效行和合并版本组成；归属记录及欠费/专线工单引用快照。原始工作簿按 SHA-256 内容寻址，同一物理文件可被多个批次引用。文件系统与 MySQL 不共享事务。

## Goals / Non-Goals

**Goals:**
- 按来源、统计期、业务键原子清除该记录的所有已解析历史及关联工单。
- 明确预览删除整份原始工作簿的连带影响，并仅在单独确认后销毁。
- 在磁盘清理失败或进程重启时能报告并重试，不将待清理文件误报为已删除。
- 保留不含业务键或字段的最小审计记录；批次级上传汇总可继续追溯。

**Non-Goals:**
- 不删除未选中的其他业务键数据，也不自动删除数据库外部备份。
- 不提供客户经理删除权限、撤销删除、已删除记录恢复或备份清理。
- 不将永久删除动作纳入普通 Excel 合并流程。

## Decisions

### 管理员预览和一次性确认

新增管理员专用删除预览和确认 API。预览由用户选择的快照记录解析出来源/统计期/稳定业务键，汇总全部历史行、批次、工作簿和同文件其他业务键数量。服务端签发短时、单次使用且绑定操作者的预览 ID；确认时锁定相关统计期并验证预览未过期、未被使用、当前版本未变化。页面在原件删除选项单独展示批次、文件名和连带影响，要求键入“永久删除”确认。预览过期、服务重启导致临时预览丢失或数据版本变化时要求重新生成预览。

一次选择可以跨多个统计期，但一个操作只处理一种来源。数据库按来源和统计期排序加锁，避免并发导入和不同顺序的批量删除互相死锁。选择数量设有上限，超限时要求拆分操作。

### 数据库删除边界

对每个 `(source_type, statistics_key, identity_key)`，按依赖顺序删除该键在该统计期所有批次中的修订差异、工单跟进和状态历史、工单、归属异常和历史、来源专用快照、版本成员、有效行、通用快照记录及原始导入行。统计期版本头、批次级上传尝试/汇总、操作者账号和通用审计不删除；批次增加 `erased_rows` 汇总，并以空文件引用表示整份原件已销毁。未选键及其他统计期成员保持不变。

按键永久删除后，该键不再属于任何历史合并版本。若管理员日后明确重新导入包含该键的文件，导入服务可将其作为新写入处理；本次删除不建立隐藏的永久拒绝名单。

### 整份原始工作簿的销毁

预览收集所有含目标键的 `excel_source_file`。可选删除时，影响统计按共享该内容寻址文件的所有批次和所有来源/统计期计算，文件中其他键的解析后记录不删除。数据库迁移 V8 允许批次 `source_file_id` 为空，并添加 `erased_rows` 和文件清理队列表；批次详情改用左连接并显示“原件已销毁”。文件清理队列只在磁盘清理尚未完成时短暂保存经过路径校验的存储键，不保存文件内容、哈希或客户字段。

### MySQL 与文件系统的清理编排

确认时使用单个 MySQL 事务：锁定当前统计期版本、复核所选身份，将待销毁文件的存储键写入清理队列，解除所有批次的文件引用，删除源文件元数据和所选键所有关联数据，追加只含来源/统计期/数量的审计记录。事务提交后立即消费清理队列并删除物理文件；成功后移除队列项。磁盘错误则保留队列项并返回“数据库记录已删除，原件清理待重试”，后台定时重试，批次页面及删除操作结果明确显示待完成状态。队列重试是幂等的；文件已不存在视为清理成功。

删除预览在内存中短期保存并绑定管理员身份，避免把目标业务键长期写入数据库。数据库事务是权威执行边界；临时预览丢失时只能重新预览，不能凭旧令牌扩大删除范围。

### 审计与失败处理

审计类型区分欠费和专线记录清理，`target_id` 留空；详情只含统计期、删除记录数、影响批次数及原件清理计数/结果，不写账户 ID、服务号码、集团名称、Excel 字段、文件名或存储键。MySQL 事务失败时业务删除与审计一并回滚，文件清理队列不会提交；仅数据库提交后发生的磁盘错误会保持待重试状态。

## Risks / Trade-offs

- **[误选或不可逆清理]** → 先显示所选记录及历史/文件影响，再要求输入明确确认词；仅管理员可执行。
- **[共享工作簿被整份销毁]** → 预览跨全部引用批次和统计期汇总其他受影响业务键，选项默认关闭。
- **[磁盘删除与数据库提交无法原子化]** → 使用事务性清理队列、可重试后台任务及可见待完成状态。
- **[旧批次总行数与现存明细行数不同]** → 单独显示永久清除行数，保留导入时汇总并说明它表示历史上传原始规模。
- **[大批量清理占用锁和事务日志]** → 限制一次选择的唯一键数量，允许分批执行；每个操作按统计期有序加锁。
- **[数据库备份仍含旧数据]** → 确认界面明确说明应用数据库已清理不代表外部历史备份已清理。

## Migration Plan

1. 备份目标数据库和原始工作簿存储目录；新代码尚不执行任何清理操作。
2. 人工应用 V8：使 `excel_import_batch.source_file_id` 可空，增加 `erased_rows` 与短期原件清理队列表。
3. 部署后端和前端；验证普通导入、批次详情、原件下载仍正常。
4. 用隔离数据验证预览、权限、全部关联删除、共享文件副作用、磁盘故障重试和审计脱敏。
5. 管理员从新 UI 明确选择并执行实际删除；已提交删除不支持应用级回滚。需要恢复时只能恢复删除前数据库和原始文件备份，恢复会同时恢复其它备份状态。

## Open Questions

无。原件删除为可选操作，永久记录清除为确认删除操作的固定行为，均由用户确认。
